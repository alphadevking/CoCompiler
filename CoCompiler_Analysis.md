# CoCompiler Analysis for Academic Presentation

The CoCompiler is a simple compiler and virtual machine implemented in C++ that processes a custom programming language. Its architecture follows a traditional multi-pass compilation model, with distinct phases for processing source code into executable form.

### CoCompiler Tools, Features, and Flow:

#### I. Compiler Phases (Tools & Flow):

The compilation process is orchestrated by `main.cpp` and proceeds through the following phases:

1.  **Preprocessing (`main.cpp`)**:
    *   **Tool**: Custom preprocessor logic within [`main.cpp`](main.cpp).
    *   **Functionality**: Removes single-line comments (`//`) from the source code.
    *   **Flow**: Takes raw `.cocom` source code as input.

2.  **Lexical Analysis (Lexer)**:
    *   **Tool**: `Lexer` (defined in [`include/Lexer.h`](include/Lexer.h) and implemented in [`src/Lexer.cpp`](src/Lexer.cpp)).
    *   **Functionality**: Converts the preprocessed source code into a stream of `Token` objects (defined in [`include/Tokens.h`](include/Tokens.h)). It identifies various token types including keywords (`var`, `let`, `if`, `else`, `print`, `true`, `false`), identifiers, literals (integers, floats, strings), operators (`+`, `-`, `*`, `/`, `=`, `!`, `&&`, `||`, comparison operators), and delimiters.
    *   **Flow**: Input from Preprocessing; output is a `std::vector<Token>`.

3.  **Syntax Analysis (Parser)**:
    *   **Tool**: `Parser` (defined in [`include/Parser.h`](include/Parser.h) and implemented in [`src/Parser.cpp`](src/Parser.cpp)).
    *   **Functionality**: Takes the token stream and builds an Abstract Syntax Tree (AST). The AST is composed of `ASTNode` objects (defined in [`include/AST.h`](include/AST.h)), representing the hierarchical structure of the program. It enforces the language's grammar rules.
    *   **Flow**: Input from Lexical Analysis; output is an `ASTNode*` (root of the AST).

4.  **Semantic Analysis**:
    *   **Tools**:
        *   `SymbolTable` (defined in [`include/SymbolTable.h`](include/SymbolTable.h) and implemented in [`src/SymbolTable.cpp`](src/SymbolTable.cpp)): Manages variable declarations, scopes (global and block-level), and assigns memory addresses to symbols. It checks for duplicate declarations and undeclared variables.
        *   `Compiler` (defined in [`include/Compiler.h`](include/Compiler.h) and implemented in [`src/Compiler.cpp`](src/Compiler.cpp)): Performs type checking, ensuring operations are applied to compatible data types (e.g., arithmetic on numbers, logical on booleans). It collects semantic errors.
    *   **Functionality**: Analyzes the AST for meaning and consistency. This includes type checking and symbol management.
    *   **Flow**: Input from Syntax Analysis; if semantic errors are found, compilation halts.

5.  **Intermediate Code Generation**:
    *   **Tool**: `Compiler` ([`src/Compiler.cpp`](src/Compiler.cpp)).
    *   **Functionality**: Translates the semantically validated AST into a custom bytecode format. The bytecode consists of `Bytecode` instructions (defined in [`include/Bytecode.h`](include/Bytecode.h)), which are a low-level, stack-based representation of the program. Instructions cover arithmetic, logical, control flow (jumps for `if-else`), variable loading/storing, and I/O.
    *   **Flow**: Input from Semantic Analysis; output is `std::vector<Bytecode>`.

6.  **Code Optimization**:
    *   **Tool**: `constant_fold` function within [`main.cpp`](main.cpp).
    *   **Functionality**: Performs simple constant folding optimization on the AST (e.g., `2 + 3 * 4` is evaluated to `14` at compile time). If an optimized AST is generated, new bytecode is created from it.
    *   **Flow**: Operates on the AST before final bytecode generation for execution.

7.  **Execution (Virtual Machine)**:
    *   **Tool**: `VM` (defined in [`include/VM.h`](include/VM.h) and implemented in [`src/VM.cpp`](src/VM.cpp)).
    *   **Functionality**: A stack-based virtual machine that executes the generated bytecode. It manages a stack for intermediate values and a memory array for variable storage. It handles operations like pushing literals, performing arithmetic, logical and comparison operations, variable access, control flow, string concatenation, and printing different data types.
    *   **Flow**: Input is the final bytecode and string literals; output is the program's execution results (e.g., printed values).

#### II. Language Features Supported (from `.cocom` files):

The CoCompiler's custom language supports:

*   **Variable Declarations**: Using `var` and `let` keywords (e.g., `var x = 10;`, `let y = "hello";`).
*   **Assignment**: Assigning values to variables (e.g., `x = 5;`).
*   **Literals**: Integer (`10`), Float (`5.5`), String (`"Hello"`), Boolean (`true`, `false`).
*   **Arithmetic Operations**: `+`, `-`, `*`, `/`.
*   **String Concatenation**: Using the `+` operator for strings (e.g., `"Hello, " + "World!"`).
*   **Unary Operations**: Negation (`-x`), Logical NOT (`!true`).
*   **Comparison Operators**: `>`, `<`, `>=`, `<=`, `==`, `!=`.
*   **Logical Operators**: `&&` (AND), `||` (OR).
*   **Control Flow**: `if-else` statements, including `else if` chains.
*   **Output**: `print()` statements to display values (numbers, booleans, strings).

#### III. Educational Outputs:

The CoCompiler is designed for educational purposes, providing detailed outputs at various stages, as visible in [`main.cpp`](main.cpp) and described in [`README.md`](README.md):

*   **Token Stream**: Shows the result of lexical analysis.
*   **Abstract Syntax Tree (AST)**: Visualizes the parsed program structure.
*   **Three-Address Code (TAC)**: A simplified intermediate representation (e.g., `t1 = a + b`).
*   **Control Flow Graph (CFG)**: Visualizes program flow with basic blocks and edges.
*   **Static Single Assignment (SSA) Form**: Shows TAC after variable renaming for optimization analysis.
*   **Bytecode**: Displays the generated machine-independent instructions.
